## How the checks were run

- **Test instances.** Every automatic check ran in its own test instance of
  the installed stable binary, with `HAETTY_SOCKET`, `HAETTY_STATE_DIR` and
  `HAETTY_CONFIG_DIR` under `/tmp/haetty-check/inst/<check>`, started from a
  terminal with the `CLAUDE*` variables of the helper's own session removed.
  Test windows and test daemons were stopped by PID. Nothing was sent to the
  stable instance.
- **Screen.** GNOME refuses window listing (Introspect) and screen capture
  (`org.gnome.Shell.Screenshot`: "Screenshot is not allowed") to other
  programs. haetty's own frames were read from `HAETTY_DUMP_FRAME` dumps;
  the desktop around them was judged by the person (A1, A4–A8, 25).
- **B and 26–28 without a person.** These were driven by the check helper in
  X11 (XWayland) test windows:
  - Claude Code prompts went in through a minimal client of the wire
    protocol (version 7), connected as `Control` to the test daemon's own
    socket. The client refuses any socket outside `/tmp/haetty-check/`.
  - GUI shortcuts and permission answers went in as synthetic X11 key
    events (`XSendEvent`) to the test window only. haetty takes them only
    while the window has focus.
  - Focus was moved with `_NET_ACTIVE_WINDOW` and windows were closed with
    `_NET_CLOSE_WINDOW`.
  - State came from `haetty status --json` / `--screen` on the test socket,
    the daemon's `events.log`, `xprop` and `dbus-monitor`.
  - One permission answer (in 17) went through the client with origin
    `Human`; every other answer used GUI keys.
- **Test repositories.** `/tmp/haetty-check/b` holds a small file and a
  3 MB file. `/tmp/haetty-check/orch` is for the orchestrator; its worktrees
  are in `/tmp/haetty-check/orch-tasks/`.

## Other observations (not counted as failures)

- **Own tab name and detach.** A tab's own name (Ctrl+Shift+R) is lost
  when the tab is detached and attached again, also when a new window
  takes the session by itself; it then shows Claude Code's session name and
  is saved with `custom name` 0.
- **Notification text.** The notification of 13 carries the tab name. For a
  Claude Code tab that is Claude Code's session name, made from the first
  prompt ("notes.txt 끝에 줄 추가").
- **Large files.** The status panel's "last edit" for the 3 MB file shows
  `+0 -0`, and the working tree view says "larger than 2 MiB" (the size
  limit).
- **Crashed daemon.** A daemon killed with SIGKILL stays a zombie of the
  window that started it until that window exits. Its per-session settings
  files (`$XDG_RUNTIME_DIR/haetty/settings-<session>.json`) stayed behind
  once (first run); later runs left none.
- **Shared runtime directory.** A test instance with its own
  `HAETTY_SOCKET` still writes those settings files into the shared
  `$XDG_RUNTIME_DIR/haetty/`.
- **Inherited variables.** A Claude Code tab started from a shell that runs
  inside Claude Code inherits `CLAUDE_CODE_CHILD_SESSION` and the messaging
  socket and token; Claude Code then turns transcript saving off ("inherited
  CLAUDE_CODE_CHILD_SESSION marker"). haetty passes them on unchanged.
- **Empty button side.** With `button-layout` = `:minimize,maximize,close`
  the log has `[WARN] sctk_adwaita::buttons: Ignoring unknown button type: `
  (the empty left side); the buttons are right.
- **Worker mark after a restart.** After a restart the worker tab shows `–`
  until its next turn, although its last report is stored.
