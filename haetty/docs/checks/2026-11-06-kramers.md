## How the checks without a person were run

Each check ran in its own test instance of the installed stable binary, with
`HAETTY_SOCKET`, `HAETTY_STATE_DIR` and `HAETTY_CONFIG_DIR` under
`/tmp/haetty-check/inst/<check>`. Nothing used the real stable socket, state
or config, and the real stable instance was not running. Windows were started
from a terminal, not from the launcher. Frames were read from
`HAETTY_DUMP_FRAME` dumps. Test windows and the one test daemon that outlived
its window were stopped by PID after checking their socket path.

### Log for 7 (initial window size)

`HAETTY_LOG=debug`, Wayland, scale 1.25, `--cols 80 --rows 24`. The window is
sized with the scale-1 cell (9x17), then the cell grows to 11x21 at scale
1.25 and the window keeps its size:

```
[DEBUG] haetty::render::paint: metrics: Metrics { px: 14.666667, cell_w: 9, cell_h: 17, baseline: 14, underline: 15, strike: 10, stroke: 1 }
[DEBUG] haetty::render::paint: metrics: Metrics { px: 18.333334, cell_w: 11, cell_h: 21, baseline: 17, underline: 18, strike: 12, stroke: 1 }
[INFO] haetty::app: tab 1 = session 1a1b04175bd-1 in daemon 33656, grid 64x19
[DEBUG] haetty::app: resize 740x420 px -> grid 64x19
```

Likely cause (for the development session to confirm): `App::create` takes
the scale from `el.primary_monitor()`, which winit always returns as `None`
on Wayland, so `scale0` is 1.0. The `ScaleFactorChanged` handler then updates
the font and padding but keeps the window's inner size instead of asking for
the size of the requested grid.

### Other observations (not failures)

- `kill -TERM` of a test window left its two sessions running in the daemon,
  as after a crash. Closing the window normally ends them (README). Whether a
  logout, which ends programs with SIGTERM, should keep or end them is a
  design question.
- On Wayland an OSC 52 copy sent before the window ever had keyboard focus
  is dropped without a log line at the default level.
