## Focus stops (20:43 and 02:00)

- Both Windows parts stopped 16 to 18 s after their start, at the first focus check ("the haetty window is not in the
  foreground: stopping without sending more keys"), as in the 2026-11-10 night run. Nobody was at the PC: the
  desktop-idle counter read 2778 s (20:43 run) and 8968 s (02:00 run) at the Windows start and kept rising.
- 20:43 run: at 21:56 the foreground window was an **elevated** Windows Terminal, the one running Claude Code on this
  PC (HANDOFF §6.1 item 30 asks for the soak to be started from a PowerShell window, not from Claude Code). The task
  runs with run level Limited. Windows (UIPI) does not let a medium-integrity process inject keys into, or take the
  foreground from, an elevated window, which defeats the Alt key plus `SetForegroundWindow` step in
  `scripts/e2e/windows/lib.ps1`. In the failing runs the idle counter never reset during the Windows part (the
  injected key was rejected); in passing runs it falls to about 130 s, because the keys the soak sends count as input.
- 22:27 run: the elevated terminal was minimized at 22:19 (with the user's approval) and the non-elevated console
  window of the task was in front. The Windows soak and the GUI tabs passed. This supports the lead.
- 02:00 run: stopped at the focus check again. At 00:50 the foreground was File Explorer (not elevated) and the
  elevated terminal was still minimized; the foreground at 03:04 was not recorded. Last input was 00:35, the end of
  the 22:27 run itself. So the elevated terminal explains the 20:43 stop, but **the 02:00 stop is not explained**.
- `scripts/e2e/windows/` and `tools/overnight-soak.ps1` did not change between `bb61e92` (2026-11-09, all PASS) and
  `1163a0a`.
