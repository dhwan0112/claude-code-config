## What the first differences are (ghostty-main, one per FAIL run)

Causes seen so far (the F2 worklist; nothing changed in this stage):

- **DECRQSS for SGR** (`DCS $ q m ST`): main answers `DCS 1 $ r 0 m ST`; haetty and 0.2.2 answer nothing. 220 of the
  fuzz2 first differences are this reply alone. The reply is DEC's (VT510, DECRPSS); whether haetty should send it is
  a product decision for F2, not a difference to list.
- **A C0 control while a UTF-8 sequence is incomplete**: `vtdiff --bisect "grammar 1"` gives the minimal input `\x18`
  (CAN) after the bytes `\xf6pY\x93\x97\x99\xca3K\x06\xd4`. Main executes CAN and prints nothing; haetty prints U+0018
  as text, as 0.2.2 does. This is the grammar category's first difference in all 400 inputs, so it is probably
  one cause. ECMA-48 §5.5 gives CAN the job of cancelling; main follows it.
- The remaining text differences (fuzz2 98, mutated 66) and the replies (fuzz2 81 other) are not classified yet.

## Adapter facts (tools/ghostty-ref and haetty-vtdiff/src/refs.rs)

- Smoke: `hello` CRLF, `red` in SGR 31, a wide character and its spacer, and `e` with a combining acute: the helper's
  rows and cursor are as expected.
- The title and the working directory are taken only when valid UTF-8, else empty: haetty's mapping
  (`term.title().unwrap_or("")`, the crate returns an error for invalid UTF-8).
- Cell text and hyperlink targets are decoded with replacement, as haetty's `cell_link` does (`from_utf8_lossy`).
- An empty dump is answered `dump` alone (the reply line is trimmed); the client accepts it.
- Title report (CSI 21 t) and the glyph protocol are off on both sides (main's defaults; haetty answers neither).
- Synchronized output ends on every valid resize (main's behaviour, the same as 0.2.2's C API); nothing puts it back.
