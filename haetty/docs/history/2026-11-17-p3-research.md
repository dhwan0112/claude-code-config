## Why P3 and not P2

(`~/.local/bin/haetty` → `0.2.0-63822de98dae`), so P2 waits and P3, which needs no install, went first.

## The gate on main was failing (fixed first)

`stage.sh start` ran the gate on `29c490a` ("Release key", the person's commit filling `assets/update/haetty.pub`):
`sign::tests::keys_are_read_and_the_release_key_slot_is_empty_for_now` still asserted an empty key slot, so nothing
was committed. Fixed on main in its own gated commit: the test now checks that the slot holds one or more readable
minisign public keys and that `have_release_key()` holds. `29c490a` itself stays as pushed (a pushed failing commit
is recorded, not rewritten; check-range will list it — see HANDOFF).

Pitfall found on the way: the main checkout and a stage worktree share one cargo target directory (`tools/stage/e.sh`);
a crate built from the worktree can be taken as fresh for the main checkout (same artifact name, older mtimes), so a
test run showed the old test. `touch` the changed file, or run with `HAETTY_PROJ` set to the tree meant.

### 1. Sidebar (v1.19.5)
Files: `routes/session/sidebar.tsx`, `feature-plugins/sidebar/{context,mcp,lsp,todo,files,footer}.tsx`,
`feature-plugins/builtins.ts`. [src]

- **Side:** right. The session layout is a `flexDirection="row"` box with the chat column (`flexGrow=1`) first and
  `<Sidebar>` after it (`routes/session/index.tsx` ~L1112, L1273). [src]
- **Width: fixed `width={42}` columns**, including padding. Padding is top 1, bottom 1, left 2, right 2, which leaves
  about 38 content columns. The inner content box also has `paddingRight={1}`. [src sidebar.tsx]
  The same 42 is hard-coded in the chat width: `contentWidth = width - (sidebarVisible ? 42 : 0) - 4` (index.tsx L276).
  [dev] moves it to a constant: `ui/layout.ts: SESSION_SIDEBAR_WIDTH = 42`.
- **Borders:** none. The sidebar is set apart only by its background (`theme.backgroundPanel`, versus
  `theme.background` for the chat). It has a vertical scrollbox; the scrollbar track is `background` and the thumb is
  `borderActive`. [src]
- **Text emphasis:** each section heading is **bold** in `theme.text` (bright). Item lines use `theme.textMuted` (dim).
  Status dots `•` are colored `success` / `error` / `warning`. Diff counts use `diffAdded` / `diffRemoved`. Sections are
  separated by `gap={1}`, which is one blank line. [src]
- **Content is built from plugin slots** (`sidebar_title`, then `sidebar_content` sorted by `order`, then
  `sidebar_footer`), so third-party plugins can add sections or replace them. Top to bottom:
  1. **Title** (slot `sidebar_title`): the session title, bold in `text`. On non-`latest` channels the session ID
     follows in muted text, then the workspace label if there is one.
  2. **Context** (order 100): `N tokens`, `N% used`, `$X.XX spent`, all muted. Tokens are the input + output +
     reasoning + cache read + cache write of the last assistant message. The percentage is tokens divided by the
     model's `limit.context`. Cost is formatted as USD.
  3. **MCP** (order 200, shown only if MCP servers exist): one line per server, `• name Status`. The name is in
     `text` and the status is muted (Connected, Disabled, Needs auth, Needs client ID, or the error in italics). When
     collapsed, the heading reads `MCP (n active, m errors)`.
  4. **LSP** (order 300, always shown): one line per server, `• id root`. When the list is empty it shows a muted
     hint: "LSPs will activate as files are read" or "LSPs are disabled".
  5. **Todo** (order 400, shown only while some todo is not completed): uses the `TodoItem` component.
  6. **Modified Files** (order 500, shown only when the session diff is non-empty): `path` on the left (muted,
     **truncated from the left** to `36 - width("+a -d")` characters) and `+a` (green) / `-d` (red) right-aligned.
     These rows have no click or open handler.
  7. **Footer** (slot `sidebar_footer`, pinned below the scroll area): the cwd shown as `~/parent/` (muted) + `name`
     (bright), plus `:branch` when there is one. Below it, `• OpenCode <version>`, with a green dot, "Open" muted and
     "Code" bright. A dismissible "Getting started" card appears here when no paid provider is configured.
- **Collapsing:** a section with more than 2 items gets a `▼` / `▶` marker on its heading, and clicking the heading
  toggles it. This works by mouse only and is not persisted. [src]
- [dev] (V2) has sections Context, Limit, MCP, Todo, and Footer. LSP and Modified Files are gone from the session
  sidebar, and changed files live in the diff viewer instead.

### 2. Narrow terminals
- **Threshold:** `wide = dimensions().width > 120` (index.tsx L268) [src]. The sidebar docks automatically at
  **121 or more columns** and hides at 120 or fewer. [dev] keeps `> 120` but subtracts the vertical-tabs width first
  (`component/session-frame.tsx` L106).
- **Visibility rule** (L269-274): it is always hidden in child (subagent) sessions. It is shown if the user opened it
  for this view, or if the setting is `"auto"` and the terminal is wide.
- **Overlay, not push:** when the sidebar is open on a narrow terminal it renders inside an `position="absolute"`
  full-screen box with `alignItems="flex-end"` (so it sits at the right edge) and a scrim of `RGBA(0,0,0,70)`. That
  box is drawn over the chat, which keeps its layout (L1278-1290) [src]. (Quirk: `contentWidth` still subtracts 42
  while the overlay is shown.)
- **Setting values:** `"auto" | "hide"`. In v1 this is a persisted TUI key-value entry named `sidebar` with default
  `"auto"`, not a `tui.json` option. The open state set by the toggle is not persisted.
  [dev/docs] V2 makes it a config option: `session.sidebar`: `auto` | `hide` ("Shows the sidebar when space permits or
  always hides it"), in `services/site/src/docs/content/cli/config.mdx` L120/L138 (https://opencode.ai/docs/cli/config).
- **Toggle:** `sidebar_toggle` = `<leader>b`, where the leader defaults to `ctrl+x`, so the key is `ctrl+x b`
  (`config/keybind.ts` L41, L81). It is also in the command palette as "Hide sidebar" / "Show sidebar" (command
  `session.sidebar.toggle`). When the sidebar is visible, the toggle writes `hide`. When it is hidden, the toggle
  writes `auto` and forces it open, which on a narrow terminal shows the overlay. Documented at
  https://opencode.ai/docs/keybinds (`"sidebar_toggle": "<leader>b"`). [src + docs]

### 3. Diffs
#### a) Inline in the chat (Edit / ApplyPatch tool blocks, index.tsx ~L2326-2390) [src]
- The OpenTUI `<diff>` renderable has `view` = `"split"` (side by side) or `"unified"`, line numbers, syntax
  highlighting, and theme colors `diffAddedBg`, `diffRemovedBg`, `diffContextBg`, `diffHighlightAdded/Removed`,
  `diffLineNumber`, and `diffAdded/RemovedLineNumberBg`.
- **Rule:** if `diff_style == "stacked"` use unified, otherwise **split when `ctx.width > 120`**. Here `ctx.width` is the
  chat content width: terminal width − 42 (when the sidebar is docked) − 4. In practice, split needs **≥167 columns
  with the sidebar docked, or ≥125 without it**.
- Config: `tui.json` `"diff_style": "auto" | "stacked"` (schema `config/index.tsx` L30: "'auto' adapts to terminal
  width, 'stacked' always shows single column"). Docs: https://opencode.ai/docs/tui#options. [src + docs]
  Line wrapping uses the key-value entry `diff_wrap_mode` (`word` | `none`).
- Edit block titles: `← Edit <path>`, `← Patched <path>`, `# Created`, `# Deleted` (a deleted file shows only
  `-N lines`), `# Moved a → b`.

#### b) Full-screen diff viewer (`feature-plugins/system/diff-viewer.tsx`, 1077 lines) [src]
- **Opening it:** the slash command **`/diff`** or the palette entry "Open diff viewer" (category VCS). The `diff_open`
  keybind defaults to `none`. It opens on the git working tree. It is **not** opened from the sidebar's Modified Files
  list in v1.19.5. It is a separate route rendered as an `absolute` box with `zIndex 2500` covering the whole terminal,
  and it returns to the previous route on close.
- **Layout:** a header row reading `Diff` + muted source label ("working tree" / "main branch" / "last turn") and a
  right-aligned `N files`. Below it, a **file tree on the left at `FILE_TREE_WIDTH = 32`** (bordered panel, plus 1
  column of separator). Tree rows end in a status column: `✓` when reviewed plus `M`/`A`/`D`. The patch pane is on the
  right, with each file's header `path +a -d` followed by its patch. At the bottom is a one-line hint bar
  (`key` bright + `action` muted).
- **Split rule:** `MIN_SPLIT_WIDTH = 100`, measured on the patch pane:
  `patchPaneWidth = width − (tree ? 33 : 0) − 4`. Split is available only when that is ≥ 100, so the terminal needs
  **≥137 columns with the tree or ≥104 without it**. Below that it is forced to unified. Above it the view defaults to
  split unless `diff_style: "stacked"`. The `v` key overrides this, and the choice is persisted in the key-value entry
  `diff_viewer_view`. The tree and single-patch toggles are persisted the same way.
- **Reviewed files:** `m` marks a file reviewed. Its patch then renders muted, with no syntax colors and neutral
  backgrounds.
- **Default keys** (`config/keybind.ts` L60-75, plus the layer in diff-viewer.tsx):
  close `escape,q` · scroll `j/down`, `k/up`, `pagedown/ctrl+f`, `pageup/ctrl+b` · **next/prev hunk `]` / `[`**
  (jumps to `@@` lines) · **next/prev file `n` / `p`** · `tab` switches focus between tree and patch · tree
  `enter/space` toggles, `right` expands, `left` collapses, `E` expands all · `b` toggles the file tree · `s` single
  patch (one file at a time) · `d` switch source (working tree / main branch / last turn) · `v` split or unified ·
  `m` mark reviewed · `?` help. Mouse: click tree rows.
- [dev/docs] V2: `cli.json` `diffs.view`: `auto` | `split` | `unified`, plus `diffs.source/wrap/tree/single`. It adds
  `f` fullscreen, `ctrl+d/u` half page, `gg/G`, and `alt+down/up` for file navigation, and drops tab focus switching
  (click-only tree). Right-clicking a file in the diff sidebar gives "Mark complete". Inline split still uses
  `ctx.width > 120` and `MIN_SPLIT_WIDTH` is still 100.
  Source: https://opencode.ai/docs/cli/keybinds#diff-viewer and `cli/config.mdx` "Diffs".

### (a) What the official docs say [OFF]

- **Server side.** The IDE extension or plugin runs a local MCP server. The CLI is the client and connects to it automatically. The server is named `ide` and is hidden from `/mcp`. (OFF-VS, OFF-JB)
- **Transport.** Unencrypted `ws://`.
  - VS Code binds `127.0.0.1` on a random port in 10000–65535, and the port is not configurable.
  - JetBrains uses an OS-assigned ephemeral port. It listens on loopback only, unless the user turns on "Accept connections from all network interfaces" (meant for WSL2 or remote setups). (OFF-VS, OFF-JB)
- **Lock file.** `~/.claude/ide/<port>.lock`, or `$CLAUDE_CONFIG_DIR/ide/` when that variable is set. The file has mode `0600` in a `0700` directory. The docs do **not** list the JSON fields. (OFF-VS)
- **Auth.** Each extension activation or IDE start generates a fresh random token and writes it to the lock file. The CLI must present it in the header `X-Claude-Code-Ide-Authorization`. (OFF-VS, OFF-JB)
- **Tools.** The VS Code server "hosts a dozen tools, but only two are visible to the model": `mcp__ide__getDiagnostics` and `mcp__ide__executeCode`. JetBrains exposes only `getDiagnostics`. The rest are "internal RPC the CLI uses for its own UI, such as opening diffs, reading selections, and saving files". The docs name none of them, so they are internal and unversioned. (OFF-VS, OFF-JB)
- **Selection context.** Each prompt carries the current selection and active file. The transcript shows `⧉ Selected N lines from <file>`. A `Read` deny rule suppresses it. (OFF-VS)
- **Env vars and settings.** (OFF-ENV, OFF-SET, OFF-CLI)
  - `CLAUDE_CODE_AUTO_CONNECT_IDE`: `false` blocks auto-connect. `true` forces a connection attempt, for example when tmux hides the parent terminal. It takes precedence over `autoConnectIde`.
  - `CLAUDE_CODE_IDE_HOST_OVERRIDE`: overrides the host address (default is auto-detected, including WSL-to-Windows routing).
  - `CLAUDE_CODE_IDE_SKIP_VALID_CHECK=1`: skips validation of lock-file entries.
  - `CLAUDE_CODE_IDE_SKIP_AUTO_INSTALL=1` and `autoInstallIdeExtension`: control whether `/ide` installs the extension.
  - `autoConnectIde` (in `~/.claude.json`, default false): auto-connect from an external terminal.
  - `--ide`: "connect on startup if exactly one valid IDE is available".
  - `diffTool` (`"auto"`, the default, or `"terminal"`): `auto` opens Edit/Write diffs in the connected IDE's viewer.
  - `/ide`: connect manually from an external terminal. `/ide open` opens the project in an IDE.
  - **Not documented anywhere official:** `CLAUDE_CODE_SSE_PORT`, `ENABLE_IDE_INTEGRATION`, `FORCE_CODE_TERMINAL`, the lock JSON schema, tool names and schemas, `openDiff` semantics, notifications, and the MCP protocol version.

### (b) Third-party docs, reverse engineering, and the 2.1.326 binary

#### 1. Transport
- **Server and binding.** The editor is a WebSocket server on `127.0.0.1`, on a random free port in 10000–65535. It speaks JSON-RPC 2.0 MCP messages, one per text frame. [3P NV-PROTO, NV-SRC `server/tcp.lua`, EL-SRC `claude-code-ide-mcp-port-range`]
- **CLI client** [BIN]. The `ws-ide` transport runs:
  `new WebSocket(url, {protocols:["mcp"], headers:{"User-Agent":…, ...(authToken && {"X-Claude-Code-Ide-Authorization": authToken})}})`
  - The CLI requests subprotocol `mcp`. claudecode.nvim echoes `Sec-WebSocket-Protocol` back, and doing the same is recommended. [NV-SRC `handshake.lua`]
  - The URL is `ws://<host>:<port>` when the lock has `transport:"ws"`. Otherwise the CLI falls back to the legacy `http://<host>:<port>/sse` (`sse-ide`).
  - The host is `CLAUDE_CODE_IDE_HOST_OVERRIDE`, or `127.0.0.1` (on WSL with a Windows IDE, it probes the default gateway).

#### 2. Discovery
**Lock file JSON** [3P NV-PROTO, NV `lockfile.lua`; BIN reader]:
```json
{"pid":12345,"workspaceFolders":["/abs/project"],"ideName":"Neovim","transport":"ws","authToken":"<32 hex>"}
```
- The CLI parser [BIN] reads `workspaceFolders`, `pid`, `ideName`, `transport=="ws"`, `runningInWindows`, and `authToken`.
- **The port comes from the file name** (`<port>.lock`), not from the JSON.
- Non-JSON content is parsed as a newline-separated folder list (legacy).
- Lock files are sorted newest-mtime first.

**Env vars set by editors** [3P]:
- claudecode.nvim sets `CLAUDE_CODE_SSE_PORT=<port>`, `ENABLE_IDE_INTEGRATION=true`, and `FORCE_CODE_TERMINAL=true`. [NV `terminal.lua`]
- claude-code-ide.el sets `CLAUDE_CODE_SSE_PORT`, `TERM_PROGRAM=emacs`, and `FORCE_CODE_TERMINAL=true`. [EL `claude-code-ide.el`]
- **[BIN] `ENABLE_IDE_INTEGRATION` appears 0 times in 2.1.326**, so it is legacy and dead. The CLI scrubs `CLAUDE_CODE_SSE_PORT` and `FORCE_CODE_TERMINAL` from the environments of subprocesses it spawns.

**Auto-connect decision** [BIN `Vkt`]:
- If `CLAUDE_CODE_AUTO_CONNECT_IDE===false`, the CLI never auto-connects.
- Otherwise it connects if any of these holds: `autoConnectIde`, `--ide`, `supportedTerminal`, `CLAUDE_CODE_SSE_PORT` is set, or `CLAUDE_CODE_AUTO_CONNECT_IDE===true`.
- `supportedTerminal` means a VS Code-family or JetBrains terminal, or `FORCE_CODE_TERMINAL` is set.
- In non-interactive mode, only an explicit request counts.

**Validity per lock entry** [BIN `Z0o`]:
- An entry is "valid" with status `contains-cwd` in any of these cases:
  - `CLAUDE_CODE_IDE_SKIP_VALID_CHECK` is set.
  - The lock's port equals `CLAUDE_CODE_SSE_PORT`.
  - A `workspaceFolders` entry contains the CLI's cwd.
- A folder *inside* the cwd gives the weaker status `inside-cwd`.
- **Ancestry check.** It applies in a supportedTerminal, not on WSL, and only when the port does **not** equal `CLAUDE_CODE_SSE_PORT`. The lock `pid` must be alive and must be the CLI's parent or an ancestor; otherwise the entry is skipped. The search-result summary of GitHub issue #52858 (anthropics/claude-code) describes the same check.

**Choosing an entry** [BIN]:
- If `CLAUDE_CODE_SSE_PORT` is set and exactly one valid entry has that port, it wins outright.
- Otherwise auto-connect polls every 1 s for up to 30 s. It connects only when **exactly one** entry has `workspaceContainsCwd`.
- `/ide` lists the valid entries for the user to choose from. Invalid ones are shown as unavailable.
- A third-party note gives the same rules but marks them unverified: https://github.com/small-gear-lab/claude-ide-server/issues/1 (search summary only).

#### 3. Auth [3P + BIN]
- Header `x-claude-code-ide-authorization: <authToken>`, compared on the WebSocket upgrade; a wrong value means reject.
- claudecode.nvim generates 128-bit CSPRNG hex per server start (NV CHANGELOG #259; UUIDs earlier, #56).
- **[BIN] The header is sent only when the lock has `authToken`.** claude-code-ide.el writes no `authToken` and checks nothing (EL `--create-lockfile`), which is why it still works.
- History: CVE-2025-52882 covered unauthenticated WebSocket connections from arbitrary origins in IDE extensions before 1.0.24 (fixed June 2025). https://securitylabs.datadoghq.com/articles/claude-mcp-cve-2025-52882/

#### 4. Tools and notifications
**VS Code extension tool set** [3P NV-PROTO: "12 tools", reverse-engineered]:

| Tool | Input |
|---|---|
| `openFile` | `{filePath, preview?, startText?, endText?, selectToEndOfLine?, makeFrontmost?}` |
| `openDiff` | `{old_file_path, new_file_path, new_file_contents, tab_name}` (all required strings) |
| `getCurrentSelection` | `{}` |
| `getLatestSelection` | `{}` |
| `getOpenEditors` | `{}` |
| `getWorkspaceFolders` | `{}` |
| `getDiagnostics` | `{uri?}` |
| `checkDocumentDirty` | `{filePath}` |
| `saveDocument` | `{filePath}` |
| `close_tab` | `{tab_name}` |
| `closeAllDiffTabs` | `{}` |
| `executeCode` | `{code}` |

- Results are always `{content:[{type:"text",text:…}]}`, often with JSON stringified into `text`.
- claudecode.nvim's `openDiff` input schema is JSON Schema draft-07 with `additionalProperties:false`. [NV `tools/open_diff.lua`]

**Tools the 2.1.326 CLI itself calls on the `ide` server** [BIN]:
- `openDiff`.
- `close_tab`.
- `closeAllDiffTabs`: fire-and-forget at the start of every user turn, errors ignored.
- `getDiagnostics`: `{uri:"file://…"}` before and after edits, plus `{}`. The model also sees it as `mcp__ide__getDiagnostics`.
- The other tools are only reachable by the model if exposed. Docs say they are filtered out.

**`openDiff` flow** [BIN, decision logic in `ot()` and `nt()`]:
1. The CLI only opens an IDE diff for Edit/Write permission prompts, and only when `diffTool==="auto"` and a client named `ide` is connected.
2. Arguments sent: `old_file_path == new_file_path == <abs path>` (translated to a Windows path for WSL plus a Windows IDE), `new_file_contents = <full proposed file>`, and `tab_name = "✻ [Claude Code] <basename> (<6 random chars>) ⧉"`.
3. The tool call **blocks** until the editor answers. The terminal permission dialog runs **concurrently**, and the first to answer wins. If the user answers in the terminal, the CLI ignores the late `openDiff` result and sends `close_tab {tab_name}`.
4. The CLI interprets `content[0].text` as follows:

| Response | CLI action |
|---|---|
| `FILE_SAVED`, with `content[1].text` a string | New content = `content[1].text`. **User edits made in the diff are honoured.** |
| `DIFF_REJECTED` | New content = old file, which means reject. |
| `TAB_CLOSED` | New content = the proposal unchanged, which means **accept**. |
| Anything else | Error "Not accepted". Logged; the terminal prompt stays. |

5. After the response, the CLI diffs old against new content as a single hunk:
   - **Empty diff:** deny with "User denied via IDE". This includes FILE_SAVED with unchanged text.
   - **Non-empty diff:** allow, and the Edit/Write input is rewritten from that hunk.
   - **The CLI writes the file itself**, and the editor must not.
   - Then it sends `close_tab`.
6. Editor-side reference responses [NV `diff.lua`; EL `-mcp-handlers.el`]:
   - Accept: `[{type:"text",text:"FILE_SAVED"},{type:"text",text:<final buffer text>}]`
   - Reject: `[{type:"text",text:"DIFF_REJECTED"},{type:"text",text:<tab_name>}]`
   - `close_tab` returns `TAB_CLOSED` (the CLI ignores the text). `closeAllDiffTabs` returns `CLOSED_<n>_DIFF_TABS`.
   - Errors use JSON-RPC errors: -32602 bad params, -32000 tool error.
7. A reconnecting CLI is a new client. It never refers to diffs from an old connection, and `tab_name` is new per call. [NV-PROTO]

**Notifications, editor to CLI.** JSON-RPC notifications with no `id`. [3P NV-PROTO; schemas confirmed in BIN]
- `selection_changed {text?, filePath?, fileUrl?, selection:{start:{line,character}, end:{line,character}, isEmpty}}`
  - Lines are 0-based. The CLI shows lines `start.line+1 … end.line+1`, minus one if `end.character==0`.
- `at_mentioned {filePath (absolute), lineStart, lineEnd}`
  - Lines are 0-based and inclusive. The CLI shows `@relpath#L<s+1>-<e+1>`.
- `log_event {eventName, eventData}`: telemetry passthrough, optional.

**Notification, CLI to editor.** After `initialize`, the CLI sends `ide_connected {pid}`. [BIN; NV-PROTO; EL]

#### 5. MCP handshake and keepalive
- **Editor servers answer `protocolVersion "2024-11-05"`.** This holds for both NV (`server/init.lua`) and EL (`claude-code-ide-mcp-version`), although NV-PROTO's prose says "based on 2025-03-26".
- **CLI side** [BIN]: the bundled MCP SDK has `LATEST_PROTOCOL_VERSION "2025-11-25"`. Its supported list is `["2025-11-25","2025-06-18","2025-03-26","2024-11-05","2024-10-07"]`, so a 2024-11-05 answer is accepted. The `initialize` `clientInfo` name is `claude-code`, with no session id. [NV-PROTO]
- **Server capabilities** answered by NV: `{logging:{}, prompts:{listChanged:true}, tools:{listChanged:true}}` and `serverInfo {name:"claudecode-neovim", version}`.
- **Methods to implement:** `initialize`, `notifications/initialized` (ignore), `tools/list`, `tools/call`, `prompts/list` (return `[]`). Unknown methods get -32601.
- **Keepalive.** NV sends WebSocket-level **ping frames every 30 s** (opcode 0x9, not MCP `ping`) and drops a client after 2× the interval without progress. EL has the same timer but disabled ("Ping causing connection issues"). Answering client pings with pongs is required by RFC 6455.

#### 6. Breakage and drift risks
- **Unofficial protocol.** Tool names, `openDiff` semantics, and lock fields are undocumented "internal RPC" [OFF-VS], so any CLI release can change them. Pin and test against a CLI version. Re-check the `FILE_SAVED`/`TAB_CLOSED` handling in the binary on upgrades.
- **Stale `CLAUDE_CODE_SSE_PORT`.** If the server restarts on a new port, the old env var leaves the CLI with "No available IDEs detected". Reports: anthropics/claude-code #42141, and #67897 (devcontainer, "regression in 2.1.170"), both seen as search summaries only. **Mitigation: keep the port stable for the life of the terminal session, or restart `claude`.**
- **Ancestry and pid check** (#52858). It bites when the lock `pid` is not an ancestor of `claude` and the port does not match `CLAUDE_CODE_SSE_PORT`.
- **Mid-2025 breakage.** The claudecode.nvim README once warned "IDE integrations are currently broken in Claude Code releases newer than v1.0.27". This came from an old README snapshot in a search result; it is fixed now (the plugin tracks 2.1.3xx).
- **Dead or changed env vars.** `ENABLE_IDE_INTEGRATION` is gone as of 2.1.326. Also as of 2.1.318 (OFF-VS, OFF-ENV), the CLI no longer auto-installs the VS Code extension.
- **Position encoding.** VS Code uses UTF-16 code units, NV uses UTF-8 bytes. The CLI only uses line numbers, so the difference is harmless today.

### Minimal recipe for a terminal emulator as the "IDE" (inferred from the sources above)
1. Bind a WebSocket server on `127.0.0.1:<random 10000–65535>`, using a stable port per emulator process.
2. Generate a 128-bit hex token.
3. Atomically write `~/.claude/ide/<port>.lock` (or under `$CLAUDE_CONFIG_DIR`) with mode `0600`:
   `{"pid":<emulator pid>,"workspaceFolders":[<cwd>],"ideName":"<name>","transport":"ws","authToken":"<tok>"}`
   Delete it on exit.
4. Spawn `claude` with `CLAUDE_CODE_SSE_PORT=<port>`. The port match alone validates the entry and auto-connects, skipping both the cwd and the pid checks. `FORCE_CODE_TERMINAL` is optional; it changes terminal detection elsewhere, so test before setting it.
5. On upgrade:
   - Check the `x-claude-code-ide-authorization` header.
   - Echo `Sec-WebSocket-Protocol: mcp`.
   - Answer `initialize` with `2024-11-05` (or echo the client's version if it is supported) and `tools.listChanged`.
   - `tools/list` returns at least `openDiff`, `close_tab`, `closeAllDiffTabs`, and `getDiagnostics` (return `[]`).
6. On `openDiff`:
   - Show the old file against `new_file_contents`.
   - Keep the request pending.
   - Accept: reply `FILE_SAVED` plus the final text.
   - Reject: reply `DIFF_REJECTED` plus `tab_name`.
   - Do not write the file.
   - Close the view on `close_tab`, which can arrive first if the user answered in the CLI.
7. Optionally send `selection_changed` and `at_mentioned`. Send WebSocket pings every 30 s and answer pongs.
