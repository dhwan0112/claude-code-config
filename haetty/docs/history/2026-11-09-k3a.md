# K3a: three kramers observations (2026-11-09)

- **Zombie.** `spawn_daemon` dropped the child handle; a daemon killed with SIGKILL stayed a zombie of the window
  that started it. The window now waits for the daemon in a thread (Unix; Windows keeps no zombies).
- **Shared runtime directory.** The per-session settings went to `private_dir()` whatever the socket was. They
  now go beside the instance's own socket (`haetty_daemon::instance_run_dir`); the stable socket's directory is the
  same as before. **Protected area (the injected settings path): for the person's review.**
- **Worker mark after a restart.** A resumed session has no report in memory. Its `SessionStart` hook carries the
  transcript path; the last report of that transcript is read (the same bounded tail as the Stop fallback), without
  counting a turn. A new session has no transcript yet, so nothing is guessed.
- Tests: `a_resumed_session_shows_the_report_its_transcript_has` (haetty-cc, Unix); `a_socket_of_its_own_gives_its_own_run_dir`
  (haetty-daemon integration).
