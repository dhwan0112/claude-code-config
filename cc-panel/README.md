# cc-panel: Claude Code workspace in tmux (ccx)

`ccx [claude arguments]` opens Claude Code on a separate tmux server (`tmux -L cc`). Each tab (tmux window) has three panes.

Layout `sidebar` (default):

- left top: Claude Code, fullscreen renderer by default (prompt fixed at the bottom, the mouse wheel scrolls the conversation; `CCX_TUI`, see Renderer below)
- left bottom: diff pane (delta), height `CCX_DIFF` (default `22%`, at least 6 rows)
- right, full height: **status panel** (session, context, orchestration, limits, cost), width `CCX_SIDEBAR` (default `22%`, at least 36 columns)

Layout `split` (`CCX_LAYOUT=split ccx`): left Claude Code · right top status panel (14 rows) · right bottom diff pane.

`CCX_SIDEBAR` and `CCX_DIFF` take a percentage (`35%`, `19.5%`) or a cell count (`50`). Defaults can also come from `~/.config/cc-panel/config`
(lines `CCX_LAYOUT=`, `CCX_SIDEBAR=`, `CCX_DIFF=`, `CCX_TUI=`; `#` comments; environment variables win). `C-a w` writes the current tab's status panel width and
diff height to that file. The layout applies to tabs opened after the change; open tabs keep theirs. `C-a d` collapses the diff pane of the current
tab to 6 rows and expands it again (to its previous height).
The top bar shows only the tabs (the key help is in the status panel, `keys` rows at the bottom, so the tab bar keeps its width for tab names). Claude Code draws no status line of its own in ccx tabs (the status panel shows that data); the terminal title and,
when ccx runs inside another tmux, that outer window are named `ccx · <active tab>`.

New tabs start in **bypass permissions** mode (see Permissions below). Nothing here changes `~/.claude/settings.json`, `~/.claude/statusline.sh` or `~/.tmux.conf`.

**Colours.** Claude Code caps its colours at 256 when `TMUX` is set in its environment, whatever `COLORTERM` says, so inside tmux its logo and the `bypass permissions on` line come out pale (#D97757 becomes palette colour 173). `left.sh` exports `CLAUDE_CODE_TMUX_TRUECOLOR=1` for the Claude pane, which lifts that cap (Claude Code 2.1.318 reads the variable; it is not in the documentation, so check it after updates), and `tmux.conf` declares RGB for the outer terminal (`terminal-features *:RGB`). Tabs opened before this change keep 256 colours until their Claude session is restarted. `CLAUDE_CODE_TMUX_TRUECOLOR= ccx` (empty) keeps the 256-colour output; `/theme` → `dark-ansi` in Claude Code uses the terminal's own 16-colour palette instead.

**Renderer.** The Claude pane runs Claude Code's fullscreen renderer (`tui: fullscreen` in ccx's `--settings`, plus `CLAUDE_CODE_NO_FLICKER=1` from `left.sh`): the prompt stays at the bottom, and the mouse wheel over the pane scrolls the conversation inside Claude Code (tmux hands the wheel to the pane while its alternate screen is on; `PgUp`/`PgDn` and `Ctrl+Home`/`Ctrl+End` scroll too, `Ctrl+O` opens the transcript viewer, where `[` writes the conversation to the pane's scrollback for tmux copy mode and `/` searches). Text selection happens inside Claude Code (copied on release); `Shift`+drag still selects with the terminal. `CCX_TUI=default` (environment or config file) gives the classic renderer, where the wheel enters tmux copy mode and the whole pane, prompt included, scrolls; `CCX_TUI=user` passes no `tui` key and leaves the choice to `~/.claude/settings.json`. The variable is needed as well as the setting: after two fullscreen starts that did not finish (a crash before the first frame), Claude Code keeps the classic renderer for that version (`fullscreenAutoDisabled` in `~/.claude.json`) and ignores the `tui` setting, your own included; `CLAUDE_CODE_NO_FLICKER=1` still wins, and such sessions are not counted. Change the renderer with `CCX_TUI`, not with `/tui` inside a ccx tab: `/tui` relaunches Claude Code without the variable, so that fallback can apply. In fullscreen Claude Code's own diff panel (`/diff`) opens by itself after the first edit when the Claude pane is at least 144 columns wide and the folder is a git repository (110 columns to open at all); close it once with `/diff` or its `✕` and Claude Code remembers (`diffSidebarOpen` in `~/.claude.json`, so it stays closed outside ccx too until you run `/diff`); ccx's diff pane is unchanged. Verified 2026-11-04 in a 155-column test tab: the panel appeared after the first `Write`; with the built-in `diff` mod disabled (`enabledPlugins` `diff@builtin: false`) Claude Code's older panel appeared instead, so that setting does not prevent it and ccx does not use it. A file created with a shell command (Bash) counts for neither panel. Tabs opened before this change keep the classic renderer until their Claude session is restarted.
ccx passes its hooks and status line to Claude Code with `--settings`, so only ccx sessions run them.

## Files

| File | Role |
|---|---|
| `~/.local/bin/ccx` | Starts or reuses session `cc` on the `-L cc` server (`CCX_SOCKET` to use another socket), adds a tab, splits it into three panes in the chosen layout (pane option `@ccx_role`: `claude`, `panel`, `diff`), gives each pane `CC_PANEL_ID`. Reads defaults from `~/.config/cc-panel/config`. Scripts live in `CCX_HOME` (default `~/.claude/cc-panel`; the server options `@ccx_home` and `@ccx_bin` tell `tmux.conf` where). Nested in another tmux: renames that outer window to `ccx`, turns `automatic-rename` off for that window only, and records it in `@ccx_outer` `ccx --save-tabs [NAME]`, `ccx --restore-tabs [NAME]` and `ccx --list-tabs` handle saved tab sets (see Saved tabs under Use) |
| `ccx_settings.py` | Builds the `--settings` JSON (`tui` from `CCX_TUI`, `autoCompactWindow` 180000, status line, hooks, ccx `ask` rules, `defaultMode: bypassPermissions` unless safe) and merges a user `--settings` value |
| `dragtab.sh` | Mouse drag on the top bar (`MouseDrag1Status`): swaps the active tab with the tab under the pointer and keeps it active |
| `tabrename.sh` | `window-renamed` hook: a tab renamed by the user renames its Claude Code session (`/rename` typed into the Claude pane); no-op when the tab already matches the session name or no claude process of the tab runs |
| `newtab.sh` | Opens a ccx tab on a given tmux socket and folder; used by `C-a C`, `C-a S` and the `+` / `safe` buttons. `--once` drops repeated clicks (lock plus 1.5 s cooldown) |
| `left.sh` | Left pane: runs `claude` with `CLAUDE_CODE_TMUX_TRUECOLOR=1` (24-bit colour inside tmux, see Colours above) and `CLAUDE_CODE_NO_FLICKER` set from `CCX_TUI` (see Renderer), then removes this tab's cache files and closes the tab Before closing it drops the tab from the saved tab set `last` (`savetabs.sh --without`) |
| `statusline-tee.sh` | Status line command of ccx sessions: saves the input JSON to `~/.cache/cc-panel/$CC_PANEL_ID.json` (atomic), renames the tab after the session name when it changed (tabs started with `CCX_TAB_RENAME=1`), and prints nothing, so Claude Code shows no status line in ccx tabs (empty output = no status line, verified with 2.1.317). Without `CC_PANEL_ID` it runs `~/.claude/statusline.sh` unchanged When the session id appears or changes (session start, `/clear`, `/resume`) it refreshes the saved tab set `last` in the background (`<id>.sid` remembers the last id) |
| `hook.sh` | `pre`: snapshot before Write/Edit/NotebookEdit (skip over 2 MB, keep 20). `post` (async): record the last edited file and who edited it, only if this edit is newer than the recorded one (edit time = when its `pre` hook ran; compare-and-replace under `flock`). `agentpre`/`agentpost` (PreToolUse/PostToolUse of the Agent tool) and `substart`/`substop` (SubagentStart/SubagentStop): orchestration records in `<id>.orch` (type, description, start/end, `STATUS: verified|blocked|needs_review` line of the worker's report, else `-`). `attn wait|ask|clear` (Stop, Notification, UserPromptSubmit, PreToolUse): sets or unsets the tab's `@ccx_attn` window option and, for `wait`/`ask`, writes a BEL to the Claude pane's tty so tmux flags the tab while it is not on screen (tab colours, see Use). Never prints, always exits 0 |
| `post.sh` | Async PostToolUse hook: runs `apply_edit.py`, then `hook.sh post` |
| `apply_edit.py` | Writes `<snap>/<tool_use_id>.after`: the pre-edit snapshot with this tool call applied (Edit: old→new, every occurrence with `replace_all`; Write: the content). Skipped when `old_string` is not in the snapshot, for NotebookEdit, non-UTF-8 files and results over 2 MB. Pruned with its snapshot (last 20) |
| `panel.py` | Status panel renderer (standard library only). Sections: `sess`, `model`, `ctx`, `workers` (orchestration: summary, running `●` lines with elapsed time and the first 40 characters of the description, last 6 finished `✓ verified` / `✗ blocked` / `? needs_review` / `- no STATUS`; in interactive sessions the Agent tool returns at once (`async_launched`) and the worker stays `●` until its SubagentStop, whose last message carries the STATUS; stop records of Claude Code's internal agents, which have no `agent_type`, are not shown; below 44 columns the duration is left out; a running worker takes one row (its description is cut to the room left) and other values wrap at spaces), `limits` (every window under `rate_limits` in the status line JSON as `name · used% · reset time`; `5h` and `7d all` always listed, `-` when absent), `cost`, `cache`, `lines`, `upd`, and `keys` (the ccx shortcuts, after a blank row; one row per key, with a short description when the pane is narrow). When the pane is short, `keys`, `cache`, `lines`, `cost` and `limits` fold first, then old finished workers; the orchestration lines stay. Below 56 columns it switches to short labels |
| `diffview.py` | Diff pane renderer (standard library + `delta`). Side by side when the pane is at least 110 columns wide (`CCX_SBS_MIN`), otherwise top/bottom with a note in the header; it switches back when the pane gets wider (resize or `C-a z`). The header is cut by display width (wide characters count 2) and the screen is cleared and recomputed at once when the pane size changes |
| `savesize.sh` | `C-a w`: writes the current tab's status panel width and diff height (percent, one decimal) as `CCX_SIDEBAR` / `CCX_DIFF` to `~/.config/cc-panel/config`, keeping other lines |
| `savetabs.sh` | `C-a W`, `ccx --save-tabs`, and (quietly) ccx after opening a tab, `left.sh` when a tab closes, `statusline-tee.sh` when a session id changes and the tmux hooks `session-window-changed`, `window-renamed`, `client-detached`: writes the open tabs (name, project folder, Claude Code session id, permissions, layout; bar order) to `~/.config/cc-panel/tabs/<socket>/<NAME>.tsv`, atomically and only when the set changed |
| `togglediff.sh` | `C-a d`: collapses the diff pane to 6 rows or expands it to the height saved in the window option `@ccx_diffh` (else 22 % of the window, at least 12 rows) |
| `outer-title.sh` | Keeps the outer tmux window (recorded in `@ccx_outer`) named `ccx · <active tab>`; run by tmux hooks (window changed/renamed/closed) and by ccx |
| `tmux.conf` | Config for the `-L cc` server only (prefix `C-a`, `set-titles` `ccx · <tab>`, bindings, hooks, tab colours: `window-status-bell-style` amber, `window-status-format` red with `?` when `@ccx_attn` is `ask`, `bell-action none`) |

Runtime data: `~/.cache/cc-panel/` (`<id>.json`, `<id>.last`, `<id>.orch`, `<id>.tabname`, `<id>.sid`, `<id>/snap/` with `.snap`/`.meta`/`.after`, `<id>.settings.json`). `<id>.orch` lives as long as the tab (it survives `/clear`, `-c` and session changes in that tab) and is removed with the tab.

## Use

- Start: `ccx` (extra arguments go to `claude`, for example `ccx --model sonnet`, `ccx -c`).
- Inside another tmux server, ccx adds the tab, renames the outer window it runs in to `ccx · <active tab>` (that window only; the outer server's config is not touched; not when the outer server is itself a ccx server) and prints `TMUX= tmux -L cc attach -t cc`. The `cc` server also sets the terminal title to `ccx · <active tab>`.
- Prefix is `C-a`; press `C-a C-a` to send a literal `C-a` to the program.
- New tab: `C-a c` (current pane's directory) · `C-a C` (asks for a folder; default is the current pane's, `~` works; a missing folder only shows a message) · `C-a S` (current directory, `--safe`) · click `+` on the top bar (same as `C-a c`) or `safe` next to it (same as `C-a S`). Repeated clicks within 1.5 s open one tab.
- Tab names start as `repo:branch` (or the folder name) and then follow the session name (`/rename`, or the title Claude Code gives the session), up to 20 characters, with `#`, `;`, quotes, backslash, `$`, backtick, braces and control characters removed. An empty session name puts the first name back.
- `C-a n` / `C-a p` / `C-a <number>` switch tabs · `C-a z` zoom the current pane · `C-a d` collapse/expand the diff pane · `C-a w` save the current status panel width and diff height as defaults · `C-a W` save the open tabs as the tab set `last` (see Saved tabs) · `C-a D` detach.
- Tabs: drag a tab along the top bar to move it (it swaps places with each tab the pointer crosses). `C-a ,` renames the tab, and the Claude Code session takes the same name (`tabrename.sh` types `/rename <name>` into the tab's Claude pane; the name is cleaned like a session name, 20 characters at most; when Claude Code is busy the command is queued like typed input). `/rename` inside Claude Code renames the tab as before. A tab that is not on screen turns **amber** when its Claude Code finished a turn or waits at the prompt (cleared when the tab is selected) and **red with `?`** while it waits for a permission answer or a question (cleared when the answer is given, that is at the next tool call, or a prompt is sent). The terminal stays silent (`bell-action none`); kitty does not draw blinking text, so colour is used instead.
- Scrolling: the mouse wheel over the Claude pane scrolls the conversation and the prompt stays put (fullscreen renderer, see Renderer; `PgUp`/`PgDn` work as well). Over the diff and status panes the wheel enters tmux copy mode as before.
- Saved tabs: ccx keeps the open tabs of the `cc` server as the tab set `last` in `~/.config/cc-panel/tabs/cc/last.tsv` (one line per tab: name, project folder, Claude Code session id, permissions, layout), updated when a tab is opened, closed on purpose, selected or renamed, when a client detaches and when a tab's session id changes (`/clear`, `/resume`). After a reboot, a crash or `tmux -L cc kill-server`, `ccx --restore-tabs` opens every tab of `last` again in order, each in its folder with `claude --resume <session id>`, so the conversations continue; a tab whose session is already open is skipped, a missing folder is skipped with a message, and a session without a transcript (never prompted, or deleted) starts anew. When ccx starts a new server while `last` still holds tabs from the previous run, it first copies them to the set `previous` and shows a hint once after attaching (`ccx --restore-tabs previous`), because the new tab replaces `last`. `C-a W` or `ccx --save-tabs [NAME]` saves a set under a name you choose (letters, digits, `-`, `_`), `ccx --restore-tabs NAME` opens it, `ccx --list-tabs` lists the sets. Closing the last tab on purpose leaves `last` empty. Tabs that ran in a user-chosen permission mode (`ccx --permission-mode …`) come back in bypass mode; `--safe` tabs come back safe; other `claude` arguments of a tab are not saved.
- Pane size: `C-a` then arrow keys (press the arrow again within 600 ms to repeat, no prefix needed), or drag borders with the mouse.
- Pane focus: `C-a h`/`j`/`k`/`l`, `C-a o`, or click. (Arrow keys resize instead of moving focus; `C-a l` no longer jumps to the last window.)
- Diff pane (focus it first): `m` or `Tab` cycles views: last edit (default; snapshot before the edit vs that snapshot with the edit applied, so later changes to the file do not show; marked `(current file)` when it falls back to the file as it is now) → vs HEAD → whole working tree (includes changes made by Bash) · `j`/`k` line · `Space`/`b` page · `g`/`G` top/bottom · `r` refresh.
- Auto-compaction: ccx sessions compact at about 180k tokens (`autoCompactWindow: 180000` in ccx's `--settings`; `/autocompact` in a ccx tab shows "180k tokens (from settings)"). Pass `--settings '{"autoCompactWindow": 300000}'` to use another value; other sessions are not affected.
- `--settings` given to ccx is merged, not replaced: Claude Code applies only the last `--settings` flag, so ccx passes one merged value. Your keys win, except `hooks` (both sets run) and `statusLine` (ccx keeps its own and prints a warning).

## Permissions

- Each tab starts in bypass mode: ccx puts `permissions.defaultMode: "bypassPermissions"` in its `--settings` (the documented setting; no extra CLI flag). No warning dialog appears because `~/.claude/settings.json` already has `skipDangerousModePermissionPrompt: true`; without that key, expect Claude Code's bypass warning dialog (not tested here).
- Turn it off for one tab: `ccx --safe` or `CCX_SAFE=1 ccx` (also `C-a S` and the `safe` button). The global `defaultMode` then applies (auto on this machine). `C-a c` and `+` always open bypass tabs, even on a server started with `CCX_SAFE=1`.
- `ccx --permission-mode <mode>` or `ccx --dangerously-skip-permissions` goes to `claude` unchanged and ccx adds no `defaultMode` (a CLI flag beats settings anyway).
- Subagents inherit the mode. Ask rules still prompt in bypass mode, for the main session and for subagents.
- Ask rules: the global ones in `~/.claude/settings.json` (`git push *`, `git -C * push *`, `gh pr merge *`) plus ccx's own, each in a `git X` and a `git * X` form (so `git -C dir X` and `git -c k=v X` match too):
  - `git reset *--hard*`
  - `git clean *-*f*` (`-f`, `-fd`, `-xdf`, `--force`)
  - `git checkout` of the whole tree (`.`, `./`, `:/`), `git checkout -f` / `--force`
  - `git restore` of the whole tree (`.`, `./`, `:/`)
  - `git branch -D` and the `-d`+`-f` forms
  - `git * push*`
  - `gh repo delete`, `gh release delete`, `gh api` with `DELETE`/`delete`
- Not covered (these run without a prompt in bypass mode): commands wrapped in `bash -c`, `sh -c` or `eval`, shell aliases and scripts, `xargs` / `find -exec`, `git clean` with `clean.requireForce=false`, abbreviated options such as `--har`. `/usr/bin/git reset --hard` and `env git reset --hard` did prompt in the test. The patterns also over-match a little (for example `git checkout feature.` or a `git reset` whose message mentions `--hard`); those just ask.

## Requirements

`tmux` 3.2+, `python3`, `jq`, `git`, `delta` 0.20.1 (`~/.local/bin/delta`, x86_64 musl release, sha256 69dcb4043f55c29118f408c6efd30115e0a4e0a6709253343b8c8fa814ab4a31).

## Notes

- Closing a tab (Claude Code exits) removes that tab's cache files. Killing the whole server, or closing a window with `C-a &`, skips that step; at its next start ccx deletes the files of every tab that is no longer open on any of your tmux servers (windows are tagged with `@ccx_id`) unless they changed in the last 10 minutes.
- The default diff view shows only what the last Edit/Write changed. When the edit cannot be rebuilt (NotebookEdit, `old_string` not in the snapshot, non-UTF-8, over 2 MB) it compares with the current file and the header says `(current file)`; later changes by Bash or an editor show up in that case.
- The PreToolUse snapshot hook runs synchronously; PostToolUse runs with `async: true`. Measured Edit tool time on 2026-11-03 (2-3 samples each): 73-102 ms in ccx, 43-53 ms in a plain session.
- Changes to `tmux.conf` apply when the `cc` server starts again (or after `tmux -L cc source-file ~/.claude/cc-panel/tmux.conf`). Open tabs keep running.
- Saved tab sets live outside this folder, in `~/.config/cc-panel/tabs/<socket>/` (`XDG_CONFIG_HOME` is honoured), so a test server (`CCX_SOCKET=ccxt`) never touches the sets of `cc`. A set is written only when it changed and never becomes empty by itself: killing the server does not run `left.sh`, so `last` keeps every tab for `ccx --restore-tabs`. Restoring opens the tabs through ccx (`CCX_TABNAME` carries the saved name; the session name renames the tab again as usual) and costs no API call until you type a prompt.
- Edits outside the working directory still ask for permission in Claude Code; choose the "ask again next time" option to avoid changing user settings.
- Tab colours come from hooks that ccx passes with `--settings` (Stop → amber; Notification `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, `agent_needs_input` → red, `idle_prompt` → amber; UserPromptSubmit and every PreToolUse → clear, all `async`). Tabs opened before this change show no colours until their Claude session is restarted. Tested on 2026-11-04 by running `hook.sh attn` by hand against a real tab on a test socket; that the Stop/Notification hooks fire at the right moments in a real turn, and which notification type a question (AskUserQuestion) produces, was not verified. Claude Code itself rings no terminal bell inside tmux (`preferredNotifChannel` auto → no method), so the only bells on the `cc` server come from `hook.sh`.

## Development notes

- Test in `~/.cache/ccx-testdir` only, with a separate socket (`CCX_SOCKET=ccxt`, `tmux -L ccxt ...`), and kill that server afterwards. A staged copy runs with `CCX_HOME=<copy>/cc-panel <copy>/bin/ccx` (hooks, status line, scripts and bindings then all come from the copy). Run test launches with `TMUX=` unset (or from outside tmux): inside a ccx tab, the nested branch would otherwise rename that live tab. The folder is trusted once in `~/.claude.json`; a new folder for every test adds a trust entry each time. Empty the folder after a test but keep it.
- Do not reload the `cc` server or edit `hook.sh` / `left.sh` / `statusline-tee.sh` in place while tabs run: write a new file and `mv` it over the old one.
- Publishing: the baseline is the git repository `~/projects/claude-code-config` (private remote `github.com/dhwan0112/claude-code-config`; its `cc-panel/` and `bin/ccx` are what gets installed). Other computers commit too: `git pull` first, merge your changes (MANIFEST text, a new `- Updated:` line, recomputed md5 lines, `hosts/<host>.md`), commit under your own name, push, then run `tools/mirror-dropbox.sh` so `~/Dropbox/claude-code-config/current` (a mirror that pauli still reads) matches HEAD. No new `history/` folders in Dropbox.
