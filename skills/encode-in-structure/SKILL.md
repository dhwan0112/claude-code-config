# 반복은 구조로

규칙 문서와 지시문은 에이전트가 건너뛸 수 있는 권고다. 컴파일 오류와 CI 실패는 건너뛸 수 없다. 그래서 두 번 반복된 것은 글이 아니라 강제 수단으로 만든다.

## 언제 적용하는가

- 같은 리뷰 지적을 두 번째로 받았을 때
- 같은 지시를 지시 파일이나 프롬프트에 두 번째로 적으려 할 때
- 같은 종류의 버그나 되돌리기가 두 번 나왔을 때
- 주석으로 적혀 있던 제약을 옮겨야 할 때

한 번만 일어난 일은 대상이 아니다. 과하게 일반화한 규칙은 다음 작업을 막는다. 예외는 되돌릴 수 없거나 안전에 걸린 사고다. 데이터 손실, 운영 중인 시스템이나 실제 사용자 환경을 건드린 일, 자격 증명 노출은 한 번으로 충분하다.

## 절차

1. **근거 수집.** 최근 커밋과 되돌린 커밋, 리뷰 코멘트, 에이전트 지시 파일, 코드에 남은 우회책 주석을 읽는다
2. **유형으로 묶기.** 개별 사례가 아니라 실수의 종류로 묶는다. 두 번 이상 나온 유형만 다룬다
3. **가장 높은 층에서 막기.** 아래 순서에서 실제로 가능한 가장 위 층을 택한다
   1. 구조: 잘못된 사용이 불가능하게 한다. 상태의 소유자를 하나로 두기, 내부를 숨겨 잘못된 import가 실패하게 하기, 모듈 경계
   2. 타입: 잘못된 상태를 표현할 수 없게 한다. 외부 데이터는 경계에서 파싱한다
   3. 린트·CI: 금지 패턴을 검사한다. 오류 메시지에 올바른 대안을 적는다
   4. 테스트: 동작으로만 확인할 수 있는 제약
   5. 문서·에이전트 규칙: 판단이 필요해 기계로 강제할 수 없는 것만
4. **검사 검증.** 새 검사는 과거의 실제 실수에서 실패해야 한다. 그 실수를 재현해 실패를 확인하고, 현재 코드에서는 통과하는지 본다. 검사는 시도가 아니라 결과를 센다. 전제가 깨져 확인할 수 없을 때는 통과가 아니라 실패나 "실행 못 함"으로 끝나야 한다
5. **표 갱신.** 아래 표에 규칙과 강제 수단을 적는다

동작이나 공개 인터페이스가 바뀌는 인코딩, 기존 코드가 대량으로 걸리는 새 린트는 적용 전에 사용자에게 확인한다. 무인 실행에서는 이런 인코딩을 하지 않고 제안으로 남긴다.

## 비례

강제 수단은 그 실수가 다시 났을 때의 비용보다 싸야 한다.

- 인코딩은 지금 하는 변경 안에서, 통하는 가장 작은 수단으로 끝낸다. 새 CI 단계나 별도 도구처럼 본 작업보다 커지는 것은 만들지 말고 제안으로 보고한다
- 검사 때문에 매 변경의 검증 시간이 눈에 띄게 늘면 늘어난 시간을 보고에 적는다
- 검사가 원래 잡으려던 실수와 무관하게 실패하면 그 검사가 결함이다. 고치거나 지우고 표에서도 지운다

## 규칙-강제수단 표

에이전트 지시 파일(CLAUDE.md, AGENTS.md 등)에 유지한다.

| 규칙 | 강제 수단 | 위치 |
|---|---|---|
| 예: 렌더러에서 메인 프로세스 모듈 import 금지 | import 린트 규칙 | 린트 설정 파일 |
| 예: 힘 배열 단위는 eV/Å | 단위 newtype | 타입 정의 모듈 |
| 예: PR에 검증 결과 포함 | 없음 (판단 필요) | 지시 파일 |

- 강제 수단이 "없음"인 규칙이 다시 위반되면, 그 변경 안에서 한 층 올려 고친다
- 강제 수단이 생긴 규칙은 지시 파일의 서술을 한 줄로 줄인다. 강제되는 규칙을 길게 설명할 필요가 없다
- 더 이상 참이 아닌 규칙은 표와 검사에서 함께 지운다

## 도구를 만든다

같은 수작업 검증이나 변환을 두 번 했다면 스크립트, 코드모드, 생성기로 만들어 저장소에 둔다. 리뷰어가 다시 돌려 확인할 수 있어야 한다. 세션마다 일회용 스크립트를 새로 쓰지 않는다.

## 주석 금지의 강제

사용자가 원하면 주석 규칙 자체도 검사로 만든다.

1. 언어별 기성 규칙이 있으면 그것을 쓴다 (예: ESLint의 no-warning-comments, no-inline-comments). 기성 규칙이 전체 줄 주석까지 잡는지는 확인하고, 못 잡으면 그 사실을 알린다
2. 없으면 허용 패턴 목록(라이선스 헤더, 문서 주석, 링크가 있는 주석, 허용된 억제)을 둔 스크립트를 CI에 넣는다
3. 도입 전 현재 위반 수를 센다. 많으면 새 변경분에만 적용하는 방식부터 제안한다
4. 오류 메시지에는 대안을 적는다: 이름·타입으로 표현, 커밋 메시지로 이동, 제약이면 검사로 인코딩
